# パイプラインの検証記録

2026-10-03。現在の実装と固定入力で確認した結果を記録する。過去の移行途中の件数・未完了一覧は、現在の状態に置き換えた。

対象は ingestion → staging → intermediate → marts と、ループバック専用の検証画面である。配布・検索のインフラと公開方式は後段で検討する。

## 固定入力と再構築

- 採用した入力52件、原典48種類を [sources.lock.json](../pipeline/ingestion/fiscal/sources.lock.json) に固定した。採用した証跡は ingestion 配下で Git 管理する。
- 非公開 R2 `fudoki-inputs` に、取り込み表52個と原典48個の計100オブジェクトを保存し、読み戻したバイト列の SHA-256 を照合した。
- 空の別キャッシュに、正規 lock から全100オブジェクトを R2 経由で復元した。ローカルのバックアップからのコピーではない。
- 復元した入力を使い、macOS のネットワーク拒否 sandbox 内で `pipeline:build --rebuild` が成功した。通常の構築と同じ構築 ID `b-6a6dbe73a8e84aae4cd2eee96f895f75` になり、再生成した全 marts CSV のハッシュが一致した。

入力一覧は保存オブジェクトの一覧であり、財政資料の一覧とは粒度が異なる。提供用の `fiscal_datasets` は5団体・36資料を持つ。

dbt には既存設定に対する非推奨警告が残る。データ検査の警告・失敗とは区別する。

補正予算の専用検査は、取り込みと staging の行・値の一致、号数・議決日・符号・単位、当初と補正の接続、決算との集合対応、報告予算現額の欠落を検査する。各号の全ての目の増減額を、予算書の第1条に記載された歳出増減額と照合し、対象の目に変更がない号も読み飛ばさない。

時点別計算のテストでは、適用日の境界、欠号・日付・当初額・報告額の欠落、未確認の対応、M:N 対応の重複、同じ ID の金額矛盾を確認した。画面の警告表示は fixture で、現在の団体・別団体・横断検査の区別を確認した。今回の実データで dbt の警告が発生したという意味ではない。

## 補正予算の収録と照合

[補正予算の PRD](prd/fiscal-budget-history/prd.md) の対象である狛江市（132195）2023年度一般会計・歳出の二目を収録した。当初予算書と第1〜7号の補正予算書を固定し、各号の議決結果・適用日を確認した。

- 予算対象2件を `fiscal_expenditure_budget_items`、当初額2件を `fiscal_initial_expenditure_budget_lines` に収録した。
- 第1号の予備費 +1,980,000円、第3号の商工業振興費 +148,300,000円、第6号の商工業振興費 −115,000,000円を `fiscal_expenditure_budget_changes` に収録した。
- 商工業振興費の9決算明細と予備費の1決算明細、計10件を `fiscal_expenditure_settlement_links` で結び付けた。対象粒度は目であり、事業×歳出の節の対応は未確認とした。
- 決算書の87・88・114頁を画像で確認し、報告予算現額・支出済額を既収録の決算 CSV の集合と照合した。既存の歳出・歳入決算 CSV 10ファイルは補正の収録前後で変わっていない。

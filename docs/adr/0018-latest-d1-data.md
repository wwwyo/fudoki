# D1 は団体ごとの最新版だけを保持する

過去の配布物は R2 と Git manifest の履歴から取得できる。過去の提供版を API 検索する要件を外し、D1 の明細を更新ごとに複製しない。[ADR 0017](0017-jurisdiction-data-versions.md) の団体別取り込みと途中公開は維持する。

## Consequences

- `fiscal_jurisdiction_data` は団体コードを主キーとして一団体一行にする。現在の内容ハッシュはこの表だけに保持する。
- 明細・資料・予算対象・変更の主キーと外部キーから `version_id` を除く。子表と対応表には所属を識別するための複合キーを残す。
- 内容が変わると、選んだ団体の古い行・配布参照を除去して新しい行を順次取り込む。同じ内容の再試行は既存行と登録時刻を保持する。
- 最新版には全収録年度・文書種別・変更履歴を含める。最新年度だけに絞らない。
- API の内容ハッシュ指定は現在との一致確認に使う。古い指定・カーソルは `VERSION_EXPIRED` とし、再取得を求める。
- 原典・取り込み・過去の R2 配布物と Git の採用履歴は保持する。D1 の過去検索と、更新を跨ぐページ継続は提供しない。

新しい契約版3の DB と API を合わせて移行する。旧 DB は自動削除せず、固定入力から新しい DB を構築する。保存と再実行の詳細は [設計書](../prd/jurisdiction-versions/design-doc.md) に従う。

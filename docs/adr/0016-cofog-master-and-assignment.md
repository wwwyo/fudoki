# ADR 0016: COFOG マスタと明細への割当を分ける

状態: 採用（2026-10-01、2026-10-03 に配布・検索の保存方式を除外）

## 背景

分類コードの共通定義と、明細ごとの分類判断は別の概念である。同じ割当先を複数の階層列へ重ねて保存すると、分類の定義と結果の関係が曖昧になる。

## 決定

COFOG のコード・名称・階層・親コードは共通マスタ `cofog_master` に置く。Git の `packages/fiscal/detail.ts` の定義から現在使用するコードと祖先を生成する。

歳出明細は割り当てた粒度の `cofog_code` 一つと分類状態・根拠を持ち、上位分類はマスタの親子関係から求める。未割当には NULL のコードと明示した状態を使う。歳入に COFOG を付けない。division / group / class を別々の列に宣言しない（同じ事実が3箇所に分かれ、粒度を下げたとき片方だけ古くなる）。

粗い粒度は誤りではない。款の名称だけで決まる規則（総務費→01、民生費→10）は division 止まりが正しく、空の下位は「該当が無い」ではなく「まだ降りていない」を意味する。

分類規則は Git の宣言から中間処理で適用し、規則 ID は提供用データへ含めない。追跡はコード版・固定入力とパイプラインの検証記録で扱う。金額・分類・連結判断を上流と照合し、生成済みの表を独立編集する正本にしない。

## 結果と代替案

分類の共通定義と個々の判断を区別し、割当済みコードの参照と未割当の状態を検査できる。分類結果を独立した1対1表にする案は、明細と常に一緒に確定する判断に別の識別子を増やすため採用しない。配布・検索の物理的な保存形式は後段で検討する。

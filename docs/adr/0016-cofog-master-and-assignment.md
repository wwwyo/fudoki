# ADR 0016: COFOG マスタと明細への割当を分ける

状態: 採用（2026-10-01）

## 背景

D1 の `cofog` は明細と1対1で、分類コードの階層と明細ごとの判断を同じ表へ保存していた。同じ割当先を大分類・中分類・小分類の3列で持ち、明細を検索するたびに1対1表へ結合していた。

## 決定

COFOG 1999 のコード・名称・階層・親コードは公開版から独立した `cofog_codes` に置く。Git の `packages/fiscal/detail.ts` を唯一の定義とし、現在使用するコードと祖先を生成する。全分類の一覧を新たに管理することはしない。

`fiscal_lines` は割り当てた粒度の `cofog_code` 一つを外部キーとして持つ。分類状態・規則・根拠・連結の判断も明細に持つ。未割当には NULL のコードと明示した状態を使う。D1 の1対1の `cofog` 表を廃止する。

API の分類階層は共通マスタの親子関係から求める。publish は既存コードの定義が異なる場合に拒否し、過去の明細を別の意味へ読み替えない。分類の版を更新する場合は別途契約とキーを設計する。

R2 の分類 CSV は配布時に判断だけを調べられる別リソースとして残す。同じ dbt の割当から D1 と配布 CSV を生成し、全明細の分類・連結判断を相互検査する。R2 と D1 は編集する正本ではない。

## 結果と代替案

明細ごとに分類用の識別子をもう一度保存する必要がなくなる。割当済みのコードがマスタに存在することと、未割当の状態を制約で検査できる。階層の取得には小さな共通マスタの結合が必要となる。

1対1表を残せば原典由来の列と判断を物理的に分けられるが、API 用の派生表では金額・判断とも同じ公開版で確定するため、独立した表にする利点が小さい。配布 CSV の分離と D1 の物理表の分離は別の判断とする。

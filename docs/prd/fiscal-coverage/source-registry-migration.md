# 原典台帳への取得宣言の移行

## 完了した移行

- 原典台帳は `pipeline/ingestion/fiscal/sources.json`、構造は `sources.schema.json`。収録範囲は台帳と固定入力・現在の提供データから生成する報告で扱う。
- 旧共通TOMLの41ブロックを169原典・182取り込み宣言へ移した。CSV78、事項別明細47、補正42、決算PDF6、名称補助各4、履歴1。原典候補1,050件を自動取得対象にはしない。
- 原典URL・掲載先は台帳から参照する。CKAN経由の既存解決条件と処理順、履歴の議決資料、抽出器の設定を保持した。
- `sources:plan --json` と報告画面が台帳を読む。計画CLIは取得・OCR・固定入力の変更を実行しない。

## 実行した確認

2026-10-06の作業ツリーで、JSONのスキーマ検査と計画生成が成功した。台帳から復元した41ブロックは旧共通TOMLのdictと一致した。取得器の切替候補でも、CSV・カタログ・名称補助2種・事項別明細・履歴・補正・決算PDFの8読取り結果が旧設定と一致した。これは設定移行の確認であり、実データの再抽出・全量構築・全公開範囲の検証ではない。

既存1,050原典の観測・確認状態は変更していない。`bun run typecheck:all` と差分の空白検査も成功した。テストスイート・全量buildは未実施、lintコマンドは設定されていない。独立した再利用・品質・効率レビューでは重複するコピー処理を2箇所削減した。入力検証は維持した。

独立レビューで通常取得器の切替が支持定義の封印と衝突することを確認したため、`sources.py` の切替は保存した候補に戻した。現在の通常取得器には旧TOMLの読取りが残る。計画と旧設定の一致は、台帳の今後の変更が通常取得へ自動反映されることを意味しない。

## 次の作業

1. 通常取得器の台帳読取りと支持定義を一緒に移行する。Held5のruntime manifestが `sources.py` を固定しているため、このファイルだけ変更すると `all_sources()` が失敗する。直接の影響はHeld5の5入力で、入力一覧中の定義参照にも三鷹1・多摩ordinary-history38・狛江2020第1号2の41入力がある。
2. 多摩ordinary-historyの38入力には、改名前の `coverage.json` / `coverage.schema.json` の支持参照もある。過去の証拠を書き換えて済ませず、旧支持物の保持方法と新台帳への移行を決め、原典・取り込み表・意味が変わらないことを現在のコードで再確認する。
3. 個別取り込み器のTOML/JSONを同じ原典への処理宣言へ移す。年度・会計・版の観測結果を処理設定で上書きしない。公開状態を現在確認できていないアーカイブ原典には、その制約を残す。
4. 通常取得器と多摩決算PDF候補CLIの既定入力を台帳へ切り替える。旧TOMLは固定時の再現用入力としてのみ明示指定できるようにする。
5. 変更した支持定義を独立に確認し、原典・取り込み表の同一性、現在の全量構築と再構築を検査した後に採用する。封印の新ハッシュを計算したことだけでは検証済みとしない。

全公開年度・全会計・当初／補正／決算の事業×節の収録は引き続き未完了。台帳の設定移行件数を、取り込めた財政明細や収録完了件数として使わない。

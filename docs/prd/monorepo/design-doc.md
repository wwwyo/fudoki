# 原典の取り込みから提供用データまでを pipeline にまとめる

関連 PRD: [固定入力パイプラインの要件](prd.md)。全公開年度の入力と検査対象は[全年度収録のPRD](../fiscal-coverage/prd.md)で管理する。

## Objectives

- **Goal**: ingestion → staging → intermediate → marts を先に完成させる。原典との対応、金額・単位・粒度・分類・出典を検査し、固定入力から同じ提供用データを再構築できるようにする。取得・変換・ローカル検証を `pipeline/` にまとめ、共通の定義を `packages/` に置く。
- **Not goal**: 配布・検索のインフラ、公開 URL、配布版の保持、反映・再試行の運用方式を決めること。既存 Git 履歴の書き換え、公営企業会計の収録。

## Background

原典の取得・抽出、dbt の変換、提供用データの検査に加え、配布・検索の保存先と公開方式まで同時に設計していた。先に確定すべきなのは、原典を事業単位まで構造化し、団体や年度をまたいで比較できるデータを生成するパイプラインである。

2026-10-03 に、配布・検索のインフラ設計を後段へ戻した。原典と取り込み済みの表を保管する非公開 R2、採用した入力一覧・原典宣言を Git に置く方針は、固定入力を再構築するために維持する。

財政データの保存境界と ER 図は [予算と決算を別に保存・提供する設計](../fiscal-records/design-doc.md)、実行手順と現在の制約は [pipeline/README.md](../../../pipeline/README.md) を参照する。

## System Overview

- `pipeline/ingestion/fiscal/`: 原典の取得・取り込み、取得元の宣言、入力一覧、原典宣言。
- `pipeline/dbt/`: staging・intermediate・marts と、各層の検査。
- `pipeline/verify/`: dbt の系統・検査結果・原典との対応を読む報告とローカル検証画面。
- `packages/`: 財政の純粋な型・名称・共通定義と団体マスタ。

系統の図は dbt の `manifest.json` から生成する。モデルの追加・移動・依存変更が図へ反映されるよう、系統を手書きしない。

配布反映処理・D1用の書き出し・公開サービスのデータ参照は削除済みである。`pipeline/fdp/` は任意のローカル整形として残し、`apps/` の web・API・MCP・docs は一時的に HTTP 500 を返す。

## Detailed Design

### 原典と採用した入力を固定する

原典 CSV/PDF のバイト列を保存してから取り込み表を作る。取り込みでは原典の値・単位・科目経路を保持する。PDF 抽出は原典の内部で重複して印字された数字どうしの一致や小計・合計で確かめ、原典の行・頁との対応を残す。

原典と取り込みParquetは非公開R2に保管する。schemaVersion 3の `sources.lock.json` が各入力のキー・ハッシュ・サイズとsource宣言を固定し、独立したprovenanceは生成しない。必要な入力が欠ける、ハッシュが一致しない場合は停止し、自治体サイトの最新版で補わない。検査結果は再生成する検証レポートで確認する。

`pipeline/.cache/` は復元した入力・OCR・PDF 閲覧レイヤなどの再利用領域、`pipeline/.build/` は DuckDB・dbt の生成結果・検査結果・報告の作業領域とする。両方とも Git 管理外とし、キャッシュを原典の保管先と扱わない。生成キャッシュは原典ハッシュ・処理の版・設定で区切る。

### 各層で確定する意味を検査する

staging は原典の行と1対1を保ち、列名と型を整える。金額単位や原典の科目体系をこの層で変更しない。

intermediate で団体間の構造・金額単位を統一し、共通科目への対応、名称の解決、COFOG 分類、連結判断を適用する。判断の宣言・規則は Git に置く。分類不能や対応不明の行を捨てず、未確認状態を保持する。

marts で提供する列と粒度を確定する。原典由来の金額と風土記の判断を区別し、件数・金額・識別子・分類・出典を上流と照合する。後段が生成済みの表を独立編集する正本にならないようにする。

### 予算と決算、歳出と歳入を分ける

当初予算・補正・決算を文書種別で区別し、別年度・別資料・訂正版の明細を同一視しない。決算明細は支出済額または収入済額の `amount` 一つを持ち、原典の予算現額は内部の照合用報告値として保持する。

当初予算の基準額と変更の符号付き増減額は別に持つ。補正後総額を号ごとに足さず、未収録の変更をゼロと扱わない。予算と決算の比較は資料間の確認済み対応に基づき、多対多のリンクで金額を二重計上しない。

歳出予算は確認できた範囲で事業×歳出の節へ集約し、節より下の内訳と原典行への対応を `details_json` に保持する。節が不明、または内訳の分類・連結判断が一致しない場合は、原典行の粒度を残す。決算は原典行の実績表を保持し、全年度収録の拡張で確認済みの事業×節の集約表を追加する。歳入へ歳出の集約規則を転用しない。

団体・COFOG・歳出の節のマスタは共通の定義であり、年度や資料に属する予算対象・金額明細とは区別する。歳入に COFOG を付けず、GFSM は今回の提供対象に含めない。

### 固定入力から構築し、実資料で検査する

固定入力の復元を先に行い、復元済み入力からの dbt build はネットワークなしで実行する。新規取得と固定入力からの再構築を区別し、CI の build に自治体資料の再取得を含めない。

`pipeline:build` は dbt の変換・検査と marts の CSV 生成までを実行する。同じ構築 ID の再実行では CSV のハッシュを照合する。公開サービスの準備を条件にせず、ingestion〜marts とローカル検証を実行できる。

小さな fixture は保存形式や例外条件を検査するために使い、実資料の全量検証とは区別する。非公開入力の読取権限がない CI の成功を、全量検証済みと表示しない。実資料の収録範囲・検査結果・未確認事項は報告に残す。

### ローカル検証を構築処理の近くに置く

報告は `pipeline/verify/report/`、画面は `pipeline/verify/view/` に置く。view はループバック専用とし、原典・取り込み表・提供用データの対応、PDF の該当頁、注意点を確認できるようにする。公開 web と UI は共有しない。

Bun・uv の workspace と lock は root で共有し、ツールは mise で管理する。Python 3.13、依存の exact ピン留めと更新時の7日 cooldown、mise + age の秘密管理を維持する。

## Tasks

1. 原典の収録範囲と採用条件を固定し、原典宣言・入力一覧・ハッシュを照合する。
2. staging の1対1・原典単位保持、intermediate の共通化と判断、marts の列と粒度を検査する。
3. 当初予算・変更・決算の実資料を取り込み、同じ粒度の報告値と照合する。欠落した資料や対応不明を未確認として残す。
4. ingestion〜marts を独立した入口で実行し、公開サービスからの依存を増やさない。
5. dbt manifest 由来の系統とローカル view で原典対応を確認し、固定入力からの再構築を検証する。

## 検証と完了条件

- 原典と取り込み表の対応を辿れ、入力の欠落・ハッシュ不一致で停止する。
- staging が原典と1対1を保ち、金額と単位を保持する。
- intermediate の単位換算・科目対応・分類・連結判断を検査し、判断の根拠と未確認状態を追跡できる。
- marts の件数・金額・識別子・分類が上流と一致し、二重計上や根拠のない配賦がない。
- 予算と決算、歳出と歳入を区別し、未取得の変更をゼロや完全な復元額として扱わない。
- 同じ固定入力・コード・宣言・判断から同じ提供用データを再構築できる。
- 実資料の全量検証と fixture の検査を区別し、収録範囲と未確認事項を報告する。
- 系統を dbt manifest から生成し、CSV と PDF の原典対応をローカル view で確認できる。

## 現在の実装範囲

5団体の採用入力と証跡を固定し、martsを生成する。狛江市2023年度一般会計の二目に当初2件・補正3件・10決算リンクを追加した。非公開R2からの復元、同じ入力・コードによるCSVハッシュ照合とローカル画面の確認は実施済みである（復元・照合の手順は [pipeline/README.md](../../../pipeline/README.md)）。繰越・充用・流用、事業×節への未確認対応、公開インフラはこの完了範囲に含めない。

# 原典から提供データまでを固定入力で再構築する

## Problem

取り込み・変換・検証と公開サービスが結び付いていると、公開方式の変更や自治体サイトの更新により原典との対応を再現できなくなる。構築の成功と収録範囲の完成も区別する必要がある。

## 導出

Storyの「数字が怪しいと思ったときに、原典と合っているか・注意点が無いかを確かめる」を、固定入力からの再構築と各層の検査で支える。

## Overview

取り込みから提供用データまでをpipelineにまとめ、共通の定義をpackagesで管理する。採用した原典・取り込み表・証跡を固定し、stagingの1対1、intermediateの正規化と判断、martsの粒度と金額を検査する。現在の実装・検証範囲は本 PRD の「実装状態」と[全年度収録のPRD](../fiscal-coverage/prd.md)で管理する。

### Goals

- 固定した原典から同じ提供データを再構築できる。
- 原典と各層のデータ・判断・検査結果をローカルで確認できる。

### Non-Goals

- 配布・検索のインフラ、公開URL、配布版の保持と反映方式、公営企業会計。

## Acceptance Criteria

- [ ] データを維持する人が採用した入力を復元してネットワークなしでmartsまで構築し、同じ構築IDの再実行でCSVの一致を確認できる。
- [ ] 原典を確認する人が実際のdbt系統から原典・取り込み・提供データと検査結果を辿り、未確認事項を判断できる。
- [ ] データを維持する人が入力や証跡の欠落・ハッシュ不一致で構築の停止を確認し、更新された自治体原典への暗黙の差し替えを防げる。

## Success Metrics

- コアアクション: 原典との対応を確認する。
- 期待頻度 (cycle): 年数回。
- 数える対象: 原典と提供データの対応を辿った利用者。
- 主指標: 次の確認機会にも対応を辿れる利用者の割合。公開再開時に計測する。

## 実装状態

構造の移行と固定入力buildは実装済みである。全公開年度・全会計・全事業の入力採用と実資料検査は[全年度収録のPRD](../fiscal-coverage/prd.md)で継続し、構造の移行だけを全収録完了とは扱わない。

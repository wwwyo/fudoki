# 原典との対応をローカル画面で確認する

関連 PRD: [財政データの構築](../budget-fdp-pilot/prd.md)・[補正予算の収録](../fiscal-budget-history/prd.md)

## Problem

運営者が処理後の表を読むだけでは、どの原典行から来た値か、PDFのどの記載か、何を検査できたかが分からない。団体や資料の違い、警告、未対応行を取り違えずに確認できる道具が必要である。

## 導出

Storyの「数字が怪しいと思ったときに、原典と合っているか・注意点が無いかを確かめる」を支える、運営者のための検証ツールである。

## Overview

ローカルの共通案内から団体・年度・資料を選び、dbtの系統を俯瞰する。接続を選ぶと入力と出力を比較でき、CSVの行やPDFの記載箇所と表の行を相互に辿れる。取り込みの検証・検査・注意点・単位・出典を同じ画面で確認する。

### Goals

- 実際の処理系統と任意の行の対応を確かめる。
- PDFの内部突合とCSVの復元検査を区別する。
- 団体に関係する警告と未確認事項を見落とさず確認する。

### Non-Goals

- 公開サービス、複数団体の分析画面、原典や表の編集。
- 配布の承認ゲート、警告・失敗の原因の自動修正。
- PDF抽出の全体精度を内部突合だけで保証すること。

## Acceptance Criteria

- [x] 運営者が団体の処理系統で接続を選ぶと、実際の入力・出力と検査結果を見比べ、拡大・移動・ペインの調整を使って確認できる。
- [x] 運営者がCSVまたはPDFの行を選ぶと、対応する表の行と記載箇所へ相互に辿れ、対応のない行も区別できる。
- [x] 運営者が選んだ団体・資料について、出典・単位・検証範囲・警告・注意点を確認し、他団体や対象不明の検査と区別できる。
- [x] 運営者がローカルだけで原典を閲覧でき、公開Workerの配信物には原典PDF・ページ画像・文字層・行位置情報が含まれない。

## Success Metrics

- コアアクション: 構築後、団体の入力と出力・検査・原典対応を確認する。
- 期待頻度: パイプラインを構築するたび。
- 数える対象: 運営者の確認1回。
- 主指標: 対応がある行の確認で別の原典閲覧を必要としないこと。既知の警告・未対応行・突合範囲の見落とし0件。

実画面とデータの確認結果は PR の QA 欄に残す。

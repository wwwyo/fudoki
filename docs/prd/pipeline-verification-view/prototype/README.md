# pipeline-view prototypes（ラウンド3: 上下レイアウトの空間配分3案）

> [!NOTE]
> このディレクトリは `.agent/prototypes/pipeline-view/` からのコピー。`assets/`（原典 PDF `chiyoda-r8kaikeiyosan.pdf` と頁画像 217 枚、計 29MB）は**意図的に除外**してある。自治体の資料の写しを repo に載せると再配布にあたるため（再配布許可を確認済みなのは62団体中2団体）。再生成するには、千代田区の公開ページから当該 PDF を取得し、39–255 頁を PNG に描画して `assets/pdf-131016-p<頁>.png` として置く（頁画像が無くても PDF ビューア以外の機能はすべて動く）。

`/pipeline/<団体コード>/` を「1団体の配布物が正しいか」確かめるローカル検証ツールに作り直すための骨格案。ラウンド2 で採った「上に系統図・下に I/O パネル」の上下レイアウトを軸に、**図と I/O が縦の空間をどう分けるか**の3サブ案を比較する。主役は**全体像（系統図）→ 押すと I/O が見える**一続きの体験。本番コードは触っていない。

## 開き方

`index.html` をブラウザで開く（`file://` で動く。データは `data.js`、PDF ページ画像は `assets/` に埋め込み済み）。

- 案の切替: 下部ピッカー、キー `1`–`3` / `←` / `→`
- 団体の切替: 左上バー。年度切替: 見出しのセレクタ。どちらも URL（`?j=` `?y=`）に残る
- 図の**線を押す**とその組（入力→出力）が選択され I/O が開く。**ノードを押す**と出入りする組の候補が出る（1本なら即選択）
- I/O の行（`source_row` を持つ組）は双方向で対応する。千代田区の 原典→取り込み では左に PDF の実ページ（文字を選択できる。行を押すと PDF 上の該当箇所が強調、PDF 上の語を押すと行が選ばれる）

## 案

3案とも機能は同一（組単位 hover・辺クリック選択・I/O 左右50/50・番号バッジ・PDF ページ送り・詳細トグル・ズーム/パン）。違いは空間配分だけ。

1. **分割（split）** — 画面を上下2ペインに固定分割。上の図・下の I/O がそれぞれ独立にスクロールし（図ではパンが相当）、ページ自体はスクロールしない。境目をドラッグで比率を変えられる
2. **一体（flow）** — 1枚のページとして縦に流れる。図は抑えめの高さ（34vh）で画面上部に sticky 残留し、組を選ぶと I/O が見える位置まで自動スクロールする
3. **帯（peek）** — 組を選ぶと I/O が画面の大部分を使い、図は上部の細い帯に縮む。帯は全ノードを縮小表示するミニマップで選択中の組だけ強調し、帯の中でも組 hover・クリック選択が効く。右上のトグルで展開/縮小できる

## データ

- `data.js`: `apps/web/public/pipeline.json` の 131016・132195 分 + `data/fudoki.duckdb` から引いた各ノードの行サンプル（`source_row` 1–10、年度・direction 別）+ pkg は `data/budget/datapackages/<code>/*.csv` を直接読み（dbt view が相対パス参照のため）
- `assets/chiyoda-r8kaikeiyosan.pdf` + `assets/pdf-131016-p*.png`: provenance の `request_url` から取得した原典 PDF と頁画像。描画範囲は **39–255 頁**（`sources.toml` の `[statement."131016:2026".pages]` 宣言＝歳入 42–145・歳出 146–251 に、目次/総括と次節の先頭を前後数頁足したもの）。行→頁内位置の対応は pdfplumber の単語座標で 事業名/内訳名＋金額 を検索して求めた（`pdf-131016.json`。`hits` が行→bbox、`pages` に全描画頁の単語座標）。案1 の PDF ビューアはページ送り付きで、行を選ぶとその頁へ自動で移動する

## 評価基準（固定・変更禁止）

Gates:
- G1: 131016 と 132195 の両方で、全ノードと全辺が描かれ、各ノードに行数（数字）が出る
- G2: 図に検査・変換の種類・誤読の罠が出ていない
- G3: 組（ノード→ノード）を選ぶと、入力・出力・線がまとめて選択状態になり、I/O が開く
- G4: source_row で対応が付く組で、行を選ぶと反対側の対応行が選択される（双方向）
- G5: 千代田区の原典→取り込みで、PDF のページが表示され、文字を選択でき、出力行を選ぶと PDF 上の該当箇所が強調される（逆方向も）
- G6: コンソールにエラーが無い／apps/web のビルド入力に入らない

比較軸: 全体像の見通し / 選択から I/O までの近さ / I/O を見ながら全体像を見失わないか / ノードが増えたときのスケール

判定基準（1/3/5）:
- C1 何がどこに紐づくかが全体像から読める — 1: 線が追えない / 3: 追えるが時間がかかる / 5: 一目で流れと合流が分かる
- C2 選んだ組が明確 — 1: 何が選ばれたか分からない / 3: 分かるが入出力の区別が曖昧 / 5: 入力・出力・線が一体で選ばれ、向きも分かる
- C3 I/O を見ている間も全体像での位置が分かる — 1: 図が消える / 3: 戻れば分かる / 5: 常に見えている
- C4 行の対応が分かる — 1: 対応が出ない / 3: 片方向 / 5: 双方向で、画面外の対応行にも辿り着ける
- C5 PDF の該当箇所が分かる — 1: PDF が出ない / 3: ページは出る / 5: 行と記載が双方向に対応する

# Design Doc: ELT の再構成（ingestion + dbt + 配布パッケージ）

2026-08-22。三鷹市 令和6年度を1団体目として配布した後の再構成。

## なぜ直すか

3つの問題が同時に出た。どれも1団体では露見せず、2団体目と全量の見積りで初めて見えた。

### 1. ELT の用語が実装とずれている

AGENTS.md は Load を「原典1行を1行のまま中間表現へ」と宣言しているが、
実装の `load.ts` は FDP の列体系への正規化・識別子の付与・単位変換まで済ませている。
一般的な ELT では Load は生のまま置く段で、整形は Transform に属する。

宣言と実装がずれたまま通っていたのは、**宣言が守られているかを誰も検査していなかった**から。
層を増やしても検査が無ければ同じことが起きる。したがって境界はディレクトリ名ではなくテストで守る。

### 2. 系統（lineage）を手で書いている

`topology.ts` が段・ノード・辺を宣言し、画面がそれを描く。
「図がデータから出る」形にはなっているが、**系統の定義そのものは手書き**で、
このセッション中に2回「図と実装が食い違う」を直した。
系統は本来ツールが持つべき情報で、手作りは同じ失敗を繰り返す。

### 3. 配布物が全量では git に入らない

実測（三鷹市 令和6年度）。

| | 1団体1年度 | 62団体 × 9年度 |
|---|---|---|
| 原典 CSV（Shift_JIS） | 702 KB | 354 MB |
| 原典 Parquet（zstd） | 71 KB | **79 MB** |
| 正本+派生 CSV | **6.3 MB** | **3.5 GB** |

正本が原典の8倍に膨らんでいる。内訳を測ると、CSV 2,639 KB のうち約1/3が導出可能か定数だった。

| 内訳 | 容量 | 性質 |
|---|---|---|
| `*_source` 列（7階層） | 301 KB | `code‖label` と不一致 0 件。完全に冗長 |
| `hierarchy_path` | 170 KB | コード列から導出できる |
| 定数列（団体・年度・direction・phase） | 197 KB | 全行同じ値 |
| `budget_line_id` | 269 KB | うち約 180 KB が全行共通の接頭辞 |

## 決めたこと

### D1. 層は staging と core の2つ。intermediate は作らない

dbt の定石は staging / intermediate / core の3層だが、
**fudoki の①予算に intermediate へ入れるものが存在しない**。
`load.ts` も `transform.ts` も表記揺れの吸収を1つもしていない（正本は原文をそのまま保持している）。
空の層を先に作らない。

| 層 | 責務 |
|---|---|
| `staging` | source と1対1。rename と cast のみ。**判断を入れない** |
| `core` | COFOG 割当、団体をまたぐ整形。**ここから判断** |

**1対1をテストで縛る。** 原典との多重集合一致が「staging に判断が入っていない」ことの検査になる。
これが落ちたら staging に判断が混ざった合図で、そのとき intermediate を切る。

intermediate を切る条件（先に書いておく）:

- 2団体目で科目名の表記が割れて寄せる必要が出たとき（「こども」と「子ども」など）
- ②調達で事業者の名寄せが要るとき
- ③会議録で話者の名寄せが要るとき

いずれも「同じものだと決める」判断なので、そのとき層が要る。

### D2. 原典は Parquet でリポジトリに commit する

方針3の「原典は置かない」を**覆す**。全量 79 MB で git repo として普通の範囲に収まる。

partition は **取得の単位 = (団体コード, 年度, direction)**。理由は3つ。

1. **再取得の原子**がこれ。CKAN のリソース1件 = CSV 1本で、半分だけ取り直せない
2. 既にどこもこのキーで切ってある（`SOURCES['132047:2024']`）
3. **団体ごとに列が違う**（三鷹市には事項があり多摩市には無い）。
   同じスキーマを共有しない以上1テーブルの partition にはできず、ソースごとに別ファイルが正直

```
data/raw/jurisdiction=132047/year=2024/direction=expenditure/data.parquet
```

62団体 × 9年度 × 2 = 1,116 ファイル。
最も近い前例の Open States は (州, 会期) ごと **500以上**、さらに Bills / Votes など11種に分かれるので数千。
ファイル数が多いこと自体は前例どおりで問題にならない。

**この決定で再現性の意味が戻る。** 「成果物の版が残ること」だけでなく「原典から再生成できること」を保証できる。

⚠️ **③会議録の原典は commit できない。** `gate.redistribute` は allow 0 団体。
raw を置けるのは再配布可と判定済みの取得元だけで、これはコードで縛る。

### D3. 正本は団体ごと・全年度で1パッケージ。派生は東京全体で1つ

いまは (団体, 年度) ごとなので全量では 558 パッケージになる。
それでは

> 年をまたぐ比較も、市をまたぐ比較も、事実上できない

という PJ の出発点を、成果物の形でそのまま再現してしまう。
年度は `date:fiscal-year` の列で区別できるので、1リソースに9年分を入れる。

**団体をまたいで1つにはしない。**
三鷹市は事項、狛江市は大事業・中事業・小事業と、階層の構成そのものが違う。
これを1つの表に揃えるのは「この2つは同じ概念だ」という**判断**であり、正本には入れられない。

**したがって横断は派生の役目になる。** 揃える判断も COFOG の割当も同じ側にあるので、
派生を東京全体で1パッケージにすると、そこで初めて横断可能な表になる。
COFOG は元々そのための共通軸である。

**正本／派生の境界が、そのままパッケージの割り方になる。**

### D4. 派生から正本の複製を外す

`expenditure-cofog.csv`（3.3 MB）は `expenditure.csv`（2.6 MB）の全列コピー + COFOG 列だった。
派生は **識別子 + 判断だけ**の細いテーブルにする。

- 容量が減る
- **判断だけを取り出して読める**（いまは「fudoki が付け加えたのはどこか」を見るのに2ファイルの diff が要る）

### D5. 正本から冗長な列を外す

`*_source`（原文セル）を残していた理由は「正本を原文と突き合わせて検証できる」ためだった。
**D2 で原典が同じリポジトリに入るので、正本が原文を抱える必要がなくなった**。join すればよい。

`hierarchy_path` と定数列も同様に外す（定数はパッケージのメタデータへ）。

⚠️ `budget_line_id` は `*_source` から導出している。
`code‖label` での再構成が原文と一致することは三鷹市で実測（不一致0件）したが、
**団体ごとに検査する**（`irregularCells` が 0 でない団体では再構成が壊れる）。

## 採らなかったもの

| | 理由 |
|---|---|
| **Kestra**（オーケストレーション） | UI が見せるのは task DAG と実行履歴で、**データの系統ではない**。求めている可視化と軸が違う。常駐する JVM サーバ + DB なので「clone して動かせる」を壊し、方針3と相性が悪い。1団体1年度でスケジューリングの必要も無い。**入れる条件**: 団体ごとの失敗切り分け・原典の差分検知・9年分のバックフィル・開発者以外による実行、のいずれかが要るようになったとき |
| **GitHub Releases**（原典の配布） | 細かい partition と喧嘩する。1,116 個のアセットは貼れず、1アーカイブにまとめると「三鷹市だけ 71 KB 落とす」ができない。アセットは Git オブジェクトでないので fork にも含まれない |
| **オブジェクトストレージ**（Open States 型） | 部分取得はできるが**運用するサーバが要る**。止まった時点で chiholog と同じ死に方をする |
| **単一の `raw.duckdb`** | 1団体を取り直すとファイル全体が書き換わり、全量 300 MB の blob が毎回 git 履歴に積まれる。バイナリなので diff も効かない |
| **gzip CSV** | Data Package の仕様に `compression` プロパティが無く、拡張子からの推論も規定が無い。標準に載ることが相互運用性の主張なので、仕様外の形で配ると採用の意味が薄れる |

## 未確定（Caveats）

- **正本の形式が未決。** 冗長を削った後の実容量を測ってから決める。
  CSV のままだと全量 2.3 GB 程度と見込まれ、まだ大きい。
  Parquet は Data Package の `format` が「csv, xls, json etc.」と開いているので理論上は通るが**明記が無い**
- **1パッケージに複数年度を入れて FDP のバリデータが通るか未確認。**
  `date:fiscal-year` はそのための ColumnType なので通るはずだが確認する
- **既存の検査30件が dbt へ移った後も同じ結果を出すか。**
  移行の正しさはこれで測る。三鷹市が歳出 5,613 行・一般会計 83,187,972 千円・割当済み 5,586 行を再現することを確認してから TS 版を落とす

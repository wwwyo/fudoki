# A. 公式原典と探索範囲を調べる

## 入力と作業

- 公式の年度別索引・資料一覧・カタログ・議会資料等を辿り、対象団体・年度・会計・文書種類・補正号・版を確認する。
- 掲載ページのURLとリンク名、実ファイルのURL、確認日を記録する。取得した場合はHTTP結果・最終URL・SHA・サイズを実観測から記録する。
- CSVは実際の列・値、PDFは表紙・表見出し・物理頁等を確認する。資料名やHTTP 200だけで年度・金額段階・粒度を確定しない。
- 目・その下の事業・節が同じ資料にあることと、同じ明細で対応していることを分ける。サンプル確認を全頁・全行の確認へ広げない。

## 保存するもの

- 調査結果の一覧は `pipeline/ingestion/fiscal/sources.json`、構造は隣の `sources.schema.json` にある。
- `jurisdictions[].search_boundaries` に探索URL・確認状況等、`jurisdictions[].gaps` に年度・会計・探索の不足を残す。
- `sources[]` に掲載根拠、URL、年度・会計・版、内容確認の方法と頁付き根拠、観測粒度、事業×節の対応、未確認事項を残す。未実施の金額検査を実施済みにしない。
- 団体固有の組版・実測・失敗理由は `pipeline/ingestion/fiscal/jurisdictions/<団体コード>.md` に残す。調査中の詳細は `.agent/` や `pipeline/ingestion/fiscal/observations/` にもあるため、参照先を保持する。
- Aでは`sources.lock.json` に書き込まない。取得・確認した事実はcoverageへ記録し、B以降の抽出結果は候補の入力一覧、採用はFで扱う。provenanceの別ファイルは生成しない。

## Bへ渡す条件と限界

- 原典の識別と確認した対象範囲を渡す。会計・版・頁境界が未確認なら、その状態も渡し、別年度の確認で補わない。
- 404・403・未探索は公開資料の不存在を証明しない。探索した有限範囲と取得結果を明記する。
- 同じURLが別年度のバイト列を返す場合、掲載年と実ファイルの年の不一致を残す。同じSHAだけで掲載された旧年度の提供完了を認定しない。
- coverageへの保存は調査の記録で、固定入力への採用や提供データへの到達を意味しない。Gitへの追跡・コミット状況も別に確認する。

## 既存の調査スクリプトとの関係

- `bun run probe:documents --write` は探索観測にある資料の内容調査で、`observations/budget-document-probe.json` へ書く。本番抽出ではない。
- `bun run coverage:sources --write` は団体単位の観測を `observations/budget-source-coverage.json` へまとめる。全年度・全会計のcoverage一覧や、Gの通常監査を置き換えない。
- 現行の根拠は [全年度収録の設計書](../../../../docs/prd/fiscal-coverage/design-doc.md)、`pipeline/ingestion/fiscal/sources.json`、`probe_documents.py`、`source_coverage.py` にある。

## 既存の原典調査で実測した注意点

- **⚠️ 資料の記述より実物の列。** 設計文書が6階層と書いていた歳入が、原典では7階層だった

- **⚠️ 列があることは使われていることを意味しない。** カタログの列構成に並ぶ階層が
  全行プレースホルダのことがある。実際に使われているかは実物で測る（原則3）

- **⚠️ 構造の粒度と意味の粒度は別物。** 事業階層まで届く CSV に名称が無く、
  名称は別の資料（決算資料 PDF）からしか取れない団体があった。
  「事業単位に届いた」は名称まで取れたことを意味しない

- **⚠️「無い」と書く前に、見ていないだけではないかを疑う。** 「科目の名称は PDF にも無い」という
  結論が2度誤りだった。どちらも抽出器が読んでいない範囲を資料の性質だと読み替えていた

- **⚠️ 同名のデータセットが複数あり中身が違うことがある。** 先頭を採る実装だと
  カタログの並びが変わった日に配布物の中身が入れ替わる。複数当たったら止めて
  `resource_url_contains` の宣言を要求する

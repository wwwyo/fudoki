# C. 原典の意味と追加案の実データを検査する

## 入力と作業

- 原典、Bの候補表・候補の入力一覧・検査結果、登録コード・SQL・本体への追加一覧を読み、実行して確認する。ワーカーの成功報告だけでは通過にしない。
- 金額セルを科目番号・積算根拠から区別し、セルが属する年度・会計・単位・金額の段階を原典の見出しと照合する。同一頁の当年・前年の決算額を混ぜない。
- 目・事業・節の独立した印字小計や合計と照合する。目的別と性質別、事業別と節別など同じ金額の別の分解を足し合わせない。
- 補正では原典の符号付き基準額・増減額・補正後額を照合する。補正後総額を増減額にしたり、未収録の変更をゼロで補ったりしない。
- 未確認の承認・金額段階・事業×法定節の対応を確定値へ変えない。独立した左頁の目×節だけでは、右頁の個別事業×節を作れない。

## 登録と各層を実行して照合する

- `all_sources()` と `pipeline/ingestion/declarations.py` の実行結果で対象dataset・方向・文書種類・金額段階を確認する。辞書や関数の定義があっても返り値に入らなければ登録されない。
- 対象SQLを実行し、raw → staging → intermediate → marts → CSVの値の受け渡しを確認する。SQL文面だけの確認で終えない。
- 原典観測を保存する表では全原典列・型・値・NULL・重複数を多重集合として照合する。型付きCSVの読み込みでも空文字・NULL・数値を区別する。
- 単位換算や集約を行う提供モデルでは、宣言した変換、円への倍率、原典行ID・内訳の対応、原典行の欠落・二重収録と合計を検査する。公開CSVに全raw列がそのまま残ることを一律に要求しない。
- 実原典と既存の入力・登録を母集団にする。追加案が既存の団体・dataset・入力を落としていないか確認する。
- scopedなSQL・dbtの成功は対象範囲の証拠として保存する。全体への影響はFの全量buildで確認する。

## 保存するものと差し戻し

- 親側の照合結果は `.agent/` の作業別レビュー記録等に保存している。対象表・比較列・行数・差分・不一致と、実行した追加案を辿れるようにする。
- 科目番号の金額化、前年列の混入、列・行の欠落、段階の勝手な付与、登録漏れ・既存登録の削除があればBへ戻して修正する。
- 比較できない表を検算成功として数えない。成功件数・不一致・比較できなかった範囲を実結果に合わせて報告する。共通の提出前判定・報告生成はまだ未確立である。
- 原典の合計一致だけでは、名称の欠損、行の取り違え、同じ金額の別表の二重収録を検出できない。Cで確認した意味・値の範囲をDへ渡す。

## 現行の検査・判断の参照先

- 原典行の対応は `pipeline/dbt/tests/staging_is_one_to_one.sql`、年度・金額宣言は `amount_declarations_cover_years.sql`、`source_year_column_scope_is_real.sql` 等を参照する。
- 全列・型付きCSVの照合は `pipeline/ingestion/fiscal/tama_pre2020_coverage.py` 等の専用監査を参照する。通常監査に共通処理と資料別処理はあるが、任意の追加案を同じ提出形式で検査する共通コマンドはまだない。
- 金額段階・集約・独立した内訳の境界は [財政明細の設計](../../../../docs/prd/fiscal-records/design-doc.md) と [全年度収録の設計](../../../../docs/prd/fiscal-coverage/design-doc.md) を参照する。

## 既存の意味・宣言検査で実測した注意点

- **⚠️ 検査の分岐は、まだ来ていない団体で壊れている。** 空のプレースホルダ宣言で
  `not in ()` を書く検査、プレースホルダが1種類だと決め打ちする観測スクリプト、
  款の `addition` を想定していない対応表の検査。**3団体目で初めて動いた**

- **⚠️ 同じ事実を2箇所で宣言すると、突き合わせが粗いぶんだけ嘘が通る。**
  金額の単位は取得の宣言（`sources.toml` の団体単位）と変換の宣言（`fiscal_amounts` の
  団体 × direction × 段階）の2箇所にあり、突き合わせは **direction をまたいで合算した集合への
  メンバーシップ判定**だった。歳出が円で歳入の primary が千円の団体では、歳出のおかげで円が
  集合に入り、**歳入の primary が食い違ったまま通った**。粒度の粗い側は割れ方を表現できない以上、
  2つ目の宣言は検査の役に立たない — 取得側の宣言を消して `fiscal_amounts` に一本化した。
  **突き合わせる相手は、もう1つの宣言ではなく原典に取る**（原典の列名が `予算現額(千円)` と
  自分で単位を名乗っている）。宣言どうしの照合は、両方まとめて間違っているときに何も言わない

- **⚠️ 説明欄の段が完全な内訳とは限らない。** 段ごとの合計が一致する団体（内訳が必須）と、
  浅い段のほうが大きい団体（内訳が任意）がある。**割れていること自体を誤りにしない** —
  正しさを見るのは目の合計との突合のほう

親側のデータ検査は全ページの目視確認を意味しない。共通のページ別「親が目視確認済み」フラグは現行実装にない。`reconciled` は印字合計との一致、`amount_status` はセルの読み取り状態、page/bboxは原典位置を表す。凍結した観測や訂正宣言がある場合も、その対象範囲と全原典の確認を分ける。

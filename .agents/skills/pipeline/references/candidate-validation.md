# 形式別に取り込み表を検査する

## CSVの検査は変換に組み込む

選定済みのヘッダー付きCSVを、原典列は文字列のままParquetへ変換する。共通実装は [conversion.py](../../../../pipeline/ingestion/lib/conversion.py) の `convert_csv()` と `verify_csv()`、管理側の入口は [csv/convert.py](../../../../pipeline/ingestion/fiscal/layouts/csv/convert.py) である。

1. 上流が指定した文字コード・区切り文字・引用符を使用する。原典のSHAを変換前後に照合する。
2. ヘッダー、列数、引用符、文字コードのデコードを厳密に処理する。欠けた列や不正な文字を飛ばして継続しない。
3. Parquetを書いた後、原典CSVを先頭から読み直す。原典列の名前・順序・VARCHAR型、データ行の全セル・行順・重複・空文字を照合する。追加の物理行範囲列も照合する。
4. 不一致では停止する。共通変換は検査で拒否した新規Parquetを除去し、管理側はR2保存・管理JSON更新へ進まない。
5. 管理側のCSV変換は候補dirへ `<表ID>.checks.json` を出す。CLI全体の成功と、成否、原典SHA、変換設定、成功時の表SHA・行数を確認する。個別表の検査が通っても、原典の途中変更や別表の失敗でCLIが停止した候補は取り込み完了にしない。失敗位置は行／列で報告し、全セルをcontextへ出さない。

行数や合計だけを比べない。重複行の置換、空文字のNULL化、先頭ゼロ・空白・引用された改行の消失は、行数や合計が同じでも誤変換である。

CSVの合計が原典内で一致すること、原典の財政上の正しさ、金額の数値化は取り込みの合否条件にしない。原典に不整合があっても、その値を保持する。指定した文字コードが意味上正しいかは上流・書式設定で確認する。デコード成功と全セル一致だけで、誤った文字コード指定を必ず検出できるわけではない。

ヘッダーのみのCSVは変換関数では0行として保持できるが、管理入口では未確認の0行を拒否する。ヘッダーなし・前置き付きの専用変換と、旧Parquetを移す `retained` は、この共通CSV検査に合格済みと扱わない。

## PDFの金額検査と修正ループ

PDFは、原典の内部で重複して印字された数字どうしの一致で確かめる。保存した候補Parquetを読み戻し、階層ごとに「直下の内訳の合計＝原典に印字された親の金額」を照合する。構築コードの自己申告や、構築コード内の再計算との一致だけで合格にしない。

### 階層ごとの合計を比較する

| 集計する内訳 | 比較する原典の金額 |
| --- | --- |
| 説明欄の末端明細を、確認済みの所属に従って目・節ごとに集計 | 同じ目の法定節一覧の節額 |
| 同じ目に属する節額 | 目の金額 |
| 同じ項に属する目の金額 | 項の金額 |
| 同じ款に属する項の金額 | 款の金額 |

- 比較は同じ原典対象・会計・年度・金額段階・金額列・単位の中で行い、名称ではなく原典のコード・所属経路で区別する。検査用に数値化し、rawの原文は変えない。
- 明細に反復した親の金額は親ごとに一度だけ数え、反復値どうしが一致することも確認する。金額だけの重複除去（`SUM(DISTINCT 金額)` など）は使わない。小計と内訳、法定節一覧と説明欄・財源内訳など独立した分解を足し合わせない。
- 結果は「一致／不一致」に加え、継続頁・未読・所属未確認は「保留」、比較する印字合計や完全な内訳がない場合は「検算不可」とし理由を示す。欠けた金額を0で補わない。
- 合計一致では名称の欠損や同額の取り違えを検出できない。名称・未読セル・欠落・二重収録は、合計が合わない箇所と補正した箇所を中心に原典で確認する。

### 不一致をまとめ、修正して再検査する

1. 対象範囲の比較を一通り行い、不一致・保留・検算不可を一覧にする（階層・所属経路・原典の頁・印字合計・内訳合計・差額）。
2. 一覧を原典と照合し、欠落・二重収録・誤読・誤所属・範囲不足・原典自体の不整合を切り分ける。下位の誤りによる上位の不一致は同じ原因として扱う。
3. 抽出コード・書式設定・対象範囲を修正し、新しい候補Parquetを作る。名称の誤読は [意味照合による補正](ingestion.md#検出済み名称は意味を照合してから再読する) を先に試す。合計を合わせるための推定・配賦やParquetの直接書き換えはしない。個別訂正は [取り込み時の修正手順](ingestion.md#誤りが見つかったときの修正) に従う。
4. 影響した範囲と上位階層を再検査する。同じ問題が2回程度の修正で解消しない場合は、局所修正を続けず、階層・行の粒度・継続頁・単位・親金額の反復と、検査側の集計キーの前提を原典で見直す。
5. 不一致が解消し保留が解決した範囲を完了とする。検算不可・原典の不整合は理由を残し、検査済みの範囲と区別して報告する。既存構造の変更が必要な場合はユーザーの判断を受ける。

### PDFで併せて確認する観点

- 金額セルを科目番号・積算根拠と区別し、年度・会計・単位・金額段階を原典の見出しと照合する。当年・前年の金額列を混ぜない。
- 節一覧と説明欄は分離して構築し、同じ高さの行や名前だけで節との関係を生成していないか確認する。明細の階層は通常の列へ展開され、JSON・配列・STRUCT列や検算用の区分が混入していないこと。
- 補正は符号付き基準額・増減額・補正後額を区別する。未収録の変更をゼロにしない。

書式別の検査コードは各団体の `layouts/`（例：[昭島 text_budget](../../../../pipeline/ingestion/fiscal/jurisdictions/132071/layouts/text_budget/README.md)）、共通の見開き検算は `fiscal/layouts/fiscal_general/extract_statement.py` にある。不一致を保存前に拒否する共通条件は未実装で、CSVと同じ保証はない。

## 後段の検査へ転用するもの

登録とSQLの検査は、取り込みの内容保持と分けて [dbt](dbt.md) で行う。

- `all_sources()` と原典宣言の実行結果で対象dataset・方向・文書種類・金額段階を確認する。定義があっても返り値に入らなければ登録済みと扱わない。
- raw → staging → intermediate → marts → CSVを実行し、値と単位、原典行の対応、欠落・二重収録、集約を確認する。stagingの行数一致だけで全値一致としない。
- 単位・段階の根拠は原典から取る。宣言どうしの一致だけでは、両方が同じ誤りを含む場合に検出できない。
- 全列・型・NULL・重複数の比較を必要なモデルに適用する。提供用モデルの単位換算・集約には宣言した変換を考慮し、全raw列がそのまま残ることを要求しない。

資料別の監査やscopedなSQLの成功は、検査した範囲として報告する。全体への影響は全量build、収録範囲の完了は通常監査で確認する。

# D. 原典だけから別の場所で再抽出する

## 入力と作業

- Cで確認した原典のバイト列、提案した抽出実装、必要な宣言・モデル・補助証拠を使う。元の候補Parquetを再抽出の入力にしない。
- 別の出力先・キャッシュで処理を実行し、元の私有フォルダ・旧キー・旧パスに依存せず再構築できるか確認する。
- 処理によっては位置付き観測やOCR結果を入力にする。その場合は、原典PDFから再抽出した範囲と、保存した観測から再構築した範囲を区別し、OCR自体を再実行したとは報告しない。
- 専用処理の実際のCLI・宣言を読む。共通の再抽出コマンドは未確立で、資料別の `reconstruct`・`replay` 等を使っている。
- 再生成した表と固定予定の候補について、個別SHA・行数・型・全項目・NULL・重複数を照合する。複数回実行した場合は各回の結果を分けて残す。

## 保存するものと次へ渡せる範囲

- 移設先、入力に置いた原典・証拠の範囲、実行結果、表ごとの照合結果を `.agent/` の親側検査記録等に残す。
- 旧フォルダ用キーの参照、私有抽出器への依存、ハッシュ・型・値の不一致があればBへ戻す。採用後のコードから必要な処理・宣言を辿れるかも確認する。
- 通過は「同じ候補を再現できた」の証拠である。同じ誤りも再現するため、Cの原典の意味の検査を省略しない。
- この再抽出はFのdbt再構築とは別である。Fは採用済み取り込み表からCSVを作り直し、Dはその取り込み表の作り方を確認する。

## 現行の参照先

- 再抽出実装の例は `pipeline/ingestion/fiscal/tama_pre2020/reconstruct.py` と同ディレクトリの宣言・証拠一覧を参照する。

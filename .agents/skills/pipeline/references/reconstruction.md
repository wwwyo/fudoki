# 再抽出の適用範囲

## CSVは別工程にしない

ヘッダー付きCSVの取り込みでは、変換時に原典を再読し、Parquetの全セル・列・行・物理行範囲を照合する。この検査が通れば取り込み完了とし、別の場所で同じCSVをもう一度変換することを必須にしない。[形式別の検査](candidate-validation.md#csvの検査は変換に組み込む) を使う。

Parquetの保存・取得のSHA確認と、採用後のdbt再構築一致は、それぞれの工程で行う。CSVの再抽出と呼んで重複した判定にしない。

## PDFで転用できる再現性検査

PDFの共通フローは未確定である。抽出器の変更・移設や、原典だけから作り直せるという主張を確認するときは、従来の手順を使える。

1. ハッシュを確認した原典PDF、抽出実装、必要な書式設定・訂正宣言を使う。候補Parquetを再抽出の入力にしない。
2. 別の出力先・キャッシュで処理を実行し、元の私有フォルダ・旧key・旧pathに依存しないか確認する。
3. 位置付き観測やOCR結果を入力にする場合は、その保存物からの再構築と、原典PDFからOCRを再実行した範囲を分ける。凍結観測からの再生を原典からの再抽出と報告しない。
4. 再生成表と候補の列型・全値・NULL・重複数・原典位置を照合する。SHA一致と表の内容一致は区別する。実行環境やOCRによりバイト列の一致を保証できない場合も、その条件を明記する。
5. 入力・設定・対象範囲・結果はローカルの検査記録に残し、必要なコードと宣言は本体から辿れるようにする。

同じ候補を再現できても、同じ誤りを再現することがある。[PDFの原典照合](candidate-validation.md#pdfの既存検査を転用する) の代わりにしない。

専用処理の例は `pipeline/ingestion/fiscal/jurisdictions/132241/layouts/tama_pre2020/reconstruct.py`。共通の再抽出CLIや、全PDFに必須とする合否条件はまだない。旧Parquetをコピーする `retained` は再抽出器ではない。

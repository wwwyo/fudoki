# 原典選定から取り込み・提供用データまで

## フローを原典の形式で分ける

原典選定・保存 → 形式別の取り込みと検査 → 取り込み表の保存 → 後段への採用・dbt構築 → 収録範囲監査。

A〜Gは従来の工程識別子として参照に残すが、全形式に「候補検査C → 再抽出D」を要求しない。原典の形式に応じて、何の一致を確認するかを決める。

| 原典の形式 | 取り込み完了の条件 | 実装の状態 |
| --- | --- | --- |
| ヘッダー付きCSV | 選定原典のSHAが一致し、原典を読み直した全セル・列・行順・重複・空欄・物理行範囲がParquetと一致する | 共通CSV変換で自動検査。不一致は保存前に停止する |
| text PDF | 文字保持・原典との対応を確認し、階層別の合計検査→不一致の整理→修正・再検査を行う | 目標手順は合意済み。共通実装・書式別の停止条件は未完了 |
| scan PDF | OCRの観測と表への対応を確認し、階層別の合計検査→不一致の整理→修正・再検査を行う | OCR・再読の手順はある。合計検査の共通実装・書式別の停止条件は未完了 |

CSVは原典から保持できたことを機械的に確認すれば取り込み完了とする。原典自体の合計一致、財政上の解釈、人による全行目視、別の場所での再抽出を追加の必須工程にしない。CSVの詳細は [ingestion](ingestion.md#csv)、形式別検査の境界は [candidate-validation](candidate-validation.md) を読む。

## 保存と採用の境界

- 新しい変換入口は `ingestion:convert`。ローカル実行は候補Parquet・候補manifest・形式別の検査結果を返す。CSVの検査結果は候補dirの `<表ID>.checks.json` に置く。
- `--remote` は変換と検査を実行してから表を保存し、全表の保存成功後に対象別JSONを更新する。CSVの不一致では保存へ進まない。新しい保存には保存直後の全表読み戻しを要求せず、利用時にSHA・サイズを照合する。
- `ingestion:check` は管理情報・選定・scope・fingerprintの検査で、財政値の正しさを認定しない。`ready` も期待する表集合の状態であり、全形式の内容検査合格を表す項目ではない。
- 原典はsource_selection、表は対象・方向別のingestion領域に保存する。保存先と原典参照は管理JSONに置き、独立したprovenanceファイルを作らない。検査結果はローカルに再生成する。
- Fの入力準備は自治体の対象別JSONと保存済みParquetを読む。別のdbt用宣言JSONの提出は要求しない。旧宣言JSONを読むモデルと依存先は削除済み。残ったモデルの構築を、旧処理の全CSV再生成や公開全年度の収録完了とは扱わない。検証報告・通常監査Gには旧 `sources.lock.json` を使う経路が残る。新しい保存状態だけで内容検査や監査の完了と扱わない。[保存設計](../../../../docs/prd/ingestion-storage/design-doc.md) と [移行記録](../../../../docs/prd/ingestion-storage/migration.md) を確認する。
- [旧固定入力の保存](input-storage.md) の内容ハッシュkey・読み戻し手順は、移行中の旧経路だけに適用する。新しいCSVの取り込み条件に混ぜない。

## 後段で確認すること

取り込み後に行う年度・会計・単位・金額段階の解釈、stagingの対応、単位換算・分類・集約・CSVへの受け渡しは [採用・dbt構築](dbt.md) で確認する。取り込みの保存成功と後段の採用成功を分ける。

採用済み入力の全量buildと再構築一致は、原典から取り込み表を作る検査とは別である。[通常監査](coverage-audit.md) は現行build・提供先・年度・会計・補正号・要求粒度の不足を確認する。採用分の構築成功を全公開資料の収録完了と扱わない。

## PDFの検査を詰めるとき

subagentによる構築 → 親agentによる階層ごとの合計検査・不一致と保留の一覧化・次の対応の判断 → subagentによる修正・再構築 → 親agentによる再検査、の順で進める。不一致が繰り返す場合は、親agentが構築・検査の前提を見直して修正方針を返す。詳細は [金額検査と修正ループ](candidate-validation.md#pdfの金額検査と修正ループ) を読む。文字保持・原典との対応の検査は残し、合計一致だけで名称や行の対応まで保証しない。抽出器変更時の再現性は [reconstruction](reconstruction.md) を参照する。合意した手順と共通実装の完成を区別する。

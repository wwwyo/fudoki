# 予算の取得・PDF抽出で判明した想定外のこと

実データを通して分かった、設計時の想定と違った点。団体を問わず効くものをここに、
団体固有の癖は `jurisdictions/<団体コード>.md` に書く。

- **⚠️ HTTP を分割して読むと切り捨てが成功扱いになる。** 実際に 2.3MB のうち約 30KB を失っていた。
  引数なしの `read()` と Content-Length 突合で検知する
- **⚠️ 仕様が「正準」と宣言する taxonomy の URL は 404。**
  仕様の原文から起こして `fdp/budget-taxonomy.json` に持つ（`bun run fetch:fdp-taxonomy`）。
  「止まったら自分で維持する」が既定の運用だという最初の実例
- **⚠️ 資料の記述より実物の列。** 設計文書が6階層と書いていた歳入が、原典では7階層だった
- **⚠️ 列があることは使われていることを意味しない。** カタログの列構成に並ぶ階層が
  全行プレースホルダのことがある。実際に使われているかは実物で測る（原則3）
- **⚠️ 構造の粒度と意味の粒度は別物。** 事業階層まで届く CSV に名称が無く、
  名称は別の資料（決算資料 PDF）からしか取れない団体があった。
  「事業単位に届いた」は名称まで取れたことを意味しない
- **⚠️「無い」と書く前に、見ていないだけではないかを疑う。** 「科目の名称は PDF にも無い」という
  結論が2度誤りだった。どちらも抽出器が読んでいない範囲を資料の性質だと読み替えていた
- **款だけでは COFOG が決まらない款が実在する。** 衛生費・土木費・教育費は項へ、
  公債費・都市計画費は目へ下げて決着する
- ⚠️ **判断の粒度が、機械可読な列より細かいことがある。** COFOG の割当を長く
  division（2桁）だけで配っていたが、規則の `basis` には `04.5.1 道路交通` のような
  class まで書いてあった。**判断は class まで降りているのに、読めるのは division まで**という
  状態で、利用者が細かく集計するには文章から番号を切り出すしかなかった。
  文章に書いたことは機械可読ではない
- ⚠️ **粒度を上げると、まとめてあった規則が割れる。** 「教育総務費・小学校費・中学校費 → 09」は
  division では1本で済むが、group では 09.8 / 09.1 / 09.2 に分かれる（初等教育と中等教育は
  COFOG の group が違う）。**列を足すだけでは終わらず、規則の分割という判断が要る**
- ⚠️ **団体で畳んだ割合は、年度の主張には使えない。** 報告は長く団体単位の集計しか持たず、
  COFOG の割当率も名称の充足も全年度の合算だった。名称の載った資料が一部の年度にしか無い団体では
  合算が実態から離れる（ある団体は科目名も事業名も無い年度と、9割に付く年度が同じ数字に潰れていた）。
  **原典が年度で割れる以上、収録範囲は年度ごとにしか正しく書けない**ので、
  報告は (年度, direction) を軸にした収録状況を別に持つ（`report/budget/build.ts` の `buildCoverage`）。
  ⚠️ **分母は指標ごとに違う。** 名称は行数、COFOG の到達は割当済みの金額、
  事業名は大事業の異なり数で、混ぜると別の数字になる。
  事業名は**出所が覆う範囲**（決算書 PDF は一般会計だけ）も併記して、
  「出所が届いていない」と「届いているが当たらなかった」を分ける
- ⚠️ **名称が資料をまたぐと、汎用の規則が別団体にも当たり始める。** ある団体の科目名称を
  PDF から解決した途端、法定語彙で書いた規則（民生費 → 10 など）がその団体の繰出金の行に先に当たり、
  **会計間の繰出が「社会保護」として分類され、二重計上の注意書きが消えた**。
  繰出の規則を科目の規則より前に置いて直したが、**団体スコープの無い規則は、
  名称が増えた瞬間に適用範囲が広がる**ということ自体を憶えておく
- **⚠️ 同じ団体の同じ資料でも、年度をまたぐと表記が割れる。** 多摩市はコードのゼロ埋めが
  年度で変わり（R3 は `01`/`001`、R4 以降は `1`/`100`）、年度は `R4` という和暦の略記で入っている。
  ⚠️ **割れるのは表記だけではない。** 多摩市の令和7年度は金額の列名が変わり（`予算額` →
  `合計 / 予算額`）、**単位が千円から円になり**、歳出だけ年度の列が消えた。
  ⚠️ **粒度を丸ごと下げずに、宣言ごとの `years` で表す。** `budget_amounts` と
  `budget_source_year_columns` の各項目は任意の `years` を持て、**書かなければ全年度**である
  （解決は `dbt/macros/budget_amount_scope.sql`）。(団体, direction, 年度) へ丸ごと下げると、
  割れていない団体まで同じ宣言を年度の数だけ写経することになり、写経は片方だけ直る。
  ⚠️ **絞れるということは、絞り忘れた年度を誰も見ない状態が作れるということでもある。**
  だから覆えていない年度は `dbt/tests/amount_declarations_cover_years.sql` が、
  年度の列を外した年度に列が本当に無いかは `source_year_column_scope_is_real.sql` が、
  どちらも**原典の側を母集団にして**見る。
  ⚠️ **年度で単位が割れると、descriptor の定数に単位を置けなくなる**
  （狛江市が段階で割れたときと同じ形。配布物は `source_amount_unit` を行の列で持つ）。
  **コードで年度をまたいで突き合わせることはできない**ので、横断はマスタへの対応を介す。
  年度の列も、表記まで宣言しないと partition と比べられない
  （宣言をやめれば検査は通るが、原典が持つ年度を誰も見ていない状態になる）
- **⚠️ 原典が持たない階層がある。** 多摩市の会計は名称の列しか無くコードが存在しない。
  宣言（`budget_levels_without_code`）が無いと、staging が名称をコードとして扱い、
  「コードは数字」という検査に名称が引っかかる。**無いものを埋めない**
- **⚠️ 検査の分岐は、まだ来ていない団体で壊れている。** 空のプレースホルダ宣言で
  `not in ()` を書く検査、プレースホルダが1種類だと決め打ちする観測スクリプト、
  款の `addition` を想定していない対応表の検査。**3団体目で初めて動いた**
- **⚠️ 「宣言が何件あるか」と「段階が何種類あるか」は別。** 年度で割れた宣言を
  段階の数と取り違えると、1行しかない原典を段階ごとの行へ展開したことになる
  （主キーが `(budget_line_id, phase_id)` になり、報告の行数検算も 2 倍になる）。
  行の展開は**段階の異なり数**で決め、単位を定数にできるかは**宣言が1つか**で決める
- **⚠️ 年度で列構成そのものが違うと、Parquet の glob が開けない。**
  `union_by_name=true` で読むしかないが、そうすると**列名の書き間違いが黙って NULL になる**。
  宣言する団体は `_sources.yml` にその旨と、塞いでいる検査を書くこと
- **⚠️ 決算書は1行が複数段階の金額を持ち、段階ごとに単位も割れうる。**
  FDP は `value` の列型を1つしか持たないので package 段で段階ごとの行へ展開し、
  主キーは `(budget_line_id, phase_id)` になる。単位を descriptor の定数にできるのは1種類のときだけ
- **⚠️ 同じ事実を2箇所で宣言すると、突き合わせが粗いぶんだけ嘘が通る。**
  金額の単位は取得の宣言（`sources.toml` の団体単位）と変換の宣言（`budget_amounts` の
  団体 × direction × 段階）の2箇所にあり、突き合わせは **direction をまたいで合算した集合への
  メンバーシップ判定**だった。歳出が円で歳入の primary が千円の団体では、歳出のおかげで円が
  集合に入り、**歳入の primary が食い違ったまま通った**。粒度の粗い側は割れ方を表現できない以上、
  2つ目の宣言は検査の役に立たない — 取得側の宣言を消して `budget_amounts` に一本化した。
  **突き合わせる相手は、もう1つの宣言ではなく原典に取る**（原典の列名が `予算現額(千円)` と
  自分で単位を名乗っている）。宣言どうしの照合は、両方まとめて間違っているときに何も言わない
- **⚠️ 同名のデータセットが複数あり中身が違うことがある。** 先頭を採る実装だと
  カタログの並びが変わった日に配布物の中身が入れ替わる。複数当たったら止めて
  `resource_url_contains` の宣言を要求する
- **⚠️ 文字がアウトライン化された PDF がある。** テキスト命令を持たず全グリフが曲線として
  描かれており、テキスト抽出が原理的に成立しない。OCR（`ingestion/lib/ocr.py`）で読むが、
  **誤読が混ざる前提の経路**として扱う — 金額を原典と突合し、一致した範囲だけを使う。
  ページ全体を一度に OCR しない（列をまたぐ語の融合で座標が壊れる。列ごとに切り出す）
- **⚠️ 法定様式でも、1つの論理行が2頁にまたがることがある**（見開き）。
  頁ごとに行へまとめてから突き合わせてはいけない — 片方で名称が折り返し片方は1行、
  という行数の食い違いが普通に起きるので、行番号では対応が取れない。
  2頁の文字を1つの座標系へ合わせてから行にまとめる
- **⚠️ 同じ資料でも列の x が direction で割れる。** 歳入の目の欄は名称が折り返さない幅、
  歳出は数文字で折り返す幅、ということが実在した。片方の実測を両方へ当てると、
  一方では名称が金額の欄へ、他方では金額が欄外へこぼれる
- **⚠️ 表の欄を固定の境界で割らない。両方向にこぼれる。** 長い名前が金額側へ
  こぼれる行（1団体目）と、桁の多い金額が名前側へこぼれる行（2団体目、**30 目**が
  突合に落ちた）が両方とも実在した。境界で割ると**その行だけが丸ごと落ちる**。
  どの欄も名前が左寄せ・金額が右揃えなので、行末から数字の連なりを切り出せばよく、
  割り方は表の中に1つで足りる。同じ理由で、入れ子の段は**名前の左端ではなく金額の右端**で
  決まる（長い名前は下の段の字下げ位置を越えて右へ伸びる）
- **⚠️ 項目に通し番号を振る団体がある**（`１ 議員報酬（区議会事務局）`）。番号は目の中の
  並び順しか表していないので落とす（並びは `source_row` が保つ）。残すと年度をまたいで
  番号がずれ、同じ事業が別の名前に見える。**⚠️ 自動判定にしない** —
  番号を振らない団体では `1歳6か月児健診` のような正しい名前を削ってしまう
- **⚠️ 金額に単位が付く団体がある**（`316,980 千円`）。行末が数字で終わらないので、
  単位を落としてから切り出す。**落とせない行を弾く働きも兼ねる** —
  積算根拠の `21,400人` `98.0％` はそこで自然に除かれる
- **⚠️ 説明欄の段が完全な内訳とは限らない。** 段ごとの合計が一致する団体（内訳が必須）と、
  浅い段のほうが大きい団体（内訳が任意）がある。**割れていること自体を誤りにしない** —
  正しさを見るのは目の合計との突合のほう
- **⚠️ 款の体系が法定とまったく違う団体がある。** 2団体目に試した特別区は歳出を
  組織別に再編しており（子ども費・保健福祉費・地域振興費…）、法定の款に一対一で対応しない。
  **款コードでも款の名称でも横断できない**ので、対応先を空のまま `addition` として登録し、
  横断は COFOG に担わせることになる。人件費を1つの款に集めている団体もある。
  ⚠️ **東京62団体のうち23が特別区**なので、これは例外ではなく規模のある分岐である
- **⚠️ 見出しは継続の頁で再掲される。** 見出しを見るたびに文脈を畳むと、
  継続した明細が行き場を失って黙って落ちる。畳むのは**値が実際に変わったとき**だけにする
- **⚠️ 名前は金額と別に折り返す。しかも「次の行」が続きとは限らない。**
  説明欄には、金額だけが次行へ回る行・名前が次行へ続く行・目ごとのリード文・積算根拠が
  同居する。持ち越した名前を無条件に捨てると**項目名が途中で切れたまま配布物に出る**し、
  無条件に繋ぐとリード文や積算根拠が名前に混ざる。**行頭の字下げが揃う行だけを続きとみなす**
  （折返しは行頭が揃い、リード文と積算根拠は字下げが違う）
- **⚠️ 折り返した名称が確定するのは、その行より後である。** 名称を値でその場に写すと、
  **その科目の最初の1行だけが折返し前の名前を持つ**。金額は動かないので合計突合では出ない。
  名札を参照で持たせて、抽出が終わってから畳む
- **⚠️ 内訳を持たない科目がある**（予備費）。葉だけを行にする設計だと、
  その科目の額が配布物から丸ごと消える。科目そのものを葉として残す
- **⚠️ `IncompleteRead` は取得元の性質ではなく開発環境の問題だった。**
  原因は開発環境が通す HTTP プロキシ（切れる位置が毎回一致することから切り分け）。
  **再試行は入れない** — 本物の切断を握りつぶして失敗を遅らせるだけになり、
  「切り捨てを成功として扱わない」という取り込みの柱と逆を向く

# ELT の段名を独自定義しない

fudoki のパイプラインは「fudoki の判断が入るかどうか」で段を切るが、これは ELT（Extract/Load/Transform）という**借用した標準語彙の一般的な意味とは別軸**。

- ELT の一般的な意味: Load は生データをそのまま格納する段、Transform がそこで初めて整形・標準へのマッピングを行う段
- 過去に一度、実装（Load で FDP へのマッピングまで完了させ、Transform には COFOG 写像だけが残る形）と AGENTS.md の定義がずれ、「実装に合わせて文書を直す」判断をしたことで、**ELT という標準語を独自の意味で再定義してしまった**（Load が実質 Transform の仕事をしている状態）。この判断は後に指摘されて誤りと分かった
- AGENTS.md 方針1「独自スキーマを発明しない」は列の意味づけだけでなく、**借用した語彙の意味にも及ぶ**。段の名前を実態に合わせて書き換えるより、実態を段の名前（の標準的な意味）に合わせるほうが筋が通る

**How to apply**: パイプラインの段構成やドキュメント上の Extract/Load/Transform の説明を変更するときは、まず ELT の標準的な意味（Load=生のまま格納、Transform=変換）に照らして実装がずれていないかを先に確認する。ずれている場合、「ドキュメントを実装に合わせて書き換える」のではなく、実装を標準の意味に合わせるか、段の名前自体を実態に即した独自の語（例: 取得/正規化/判断）に変えるかを検討する。ELT という看板を掲げたまま中身だけ独自定義することは避ける。
